# 社团管理 Agent · 部署说明

> 本文档为生产部署的环境变量与依赖清单。密钥类配置一律走环境变量（prod 缺失 fail-fast），
> 部署前逐项核对，避免出现"本地能跑、生产起不来"。

## 模块与构建

| 模块 | 目录 | 技术栈 | 构建 |
|---|---|---|---|
| Java 后端 | `java/` | Spring Boot 3 + PostgreSQL + Redis | `mvn -f java/pom.xml clean package -DskipTests`，产物 `java/target/*.jar`，启动 `--spring.profiles.active=prod` |
| Python Agent | `python/` | FastAPI + LangGraph | `pip install -r requirements.txt`，`uvicorn src.agent_draft.main:app`，供 Java 侧内部调用 |
| 前端 | `frontend/` | Vue3 + Vite | `npm run build` 产物 `frontend/dist/`（静态托管 + 反代 `/api`、`/ws`） |

生产由 systemd（或容器）以固定工作目录启动 Java，建议 `WorkingDirectory=` 显式指定，不要依赖 `cd` 顺序。

## 环境变量清单

### 必设（缺失即启动失败，prod fail-fast）

| 变量 | 说明 |
|---|---|
| `SPRING_DATASOURCE_URL` / `SPRING_DATASOURCE_USERNAME` / `SPRING_DATASOURCE_PASSWORD` | PostgreSQL 连接（URL 建议带 `?currentSchema=public` 与 SSL 选项视库而定） |
| `REDIS_HOST` / `REDIS_PORT` | Redis 地址。**Redis 为强依赖单点：限流、防重、token 黑名单、会话缓存全部依赖它，故障时按 fail-closed 策略拒绝写操作，需保障可用性**（独立实例 + 持久化 + 监控告警） |
| `JWT_SECRET` | 登录签名密钥，至少 32 字节随机串，严禁复用开发值 |

### 必须指定绝对路径

| 变量 | 说明 |
|---|---|
| `LOCAL_UPLOAD_DIR` | 文件上传（头像/活动文件）存储根目录。**生产必须用环境变量指定绝对路径**（如 `/data/club-agent/uploads`），禁止依赖默认 `./uploads` 相对路径——相对路径随启动工作目录漂移，且该目录已移出版本库，目录需部署时手动创建并确保运行用户可写 |

### 建议设置（缺失不阻断，但属于部署收紧项）

| 变量 | 说明 |
|---|---|
| `AI_DRAFT_INTERNAL_SECRET` | Python Agent 内部调用密钥头 `X-Internal-Secret`。prod 无默认值：未设置时 Java 侧不带头、Python 侧跳过校验并告警——**仅限内网直连部署**；若 Python 服务暴露到不可信网络必须设置 |
| `CAPTCHA_ENABLED` | 验证码开关（开发默认关闭；生产建议 `true`） |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | AI 能力（概念起草/总结等）依赖的模型服务 |
| `UPLOAD_MAX_SIZE` | 上传大小上限，默认 5MB |

## 反向代理安全（Nginx 必配）

后端限流/防重/操作日志的 IP 维度读取 `X-Forwarded-For` 首段（见 IpUtils）——**该头客户端可伪造，Nginx 必须覆盖为真实来源 IP**，否则攻击者可伪造头绕过限流与失败锁定：

```nginx
location / {
    proxy_set_header X-Forwarded-For $remote_addr;   # 覆盖而非追加：丢弃客户端伪造值
    proxy_set_header X-Real-IP $remote_addr;
    proxy_pass http://127.0.0.1:8093;
}
```

WebSocket 升级（/ws）同样需要 `proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade";`。

## 运维注意

- 数据库迁移：`scripts/` 下建表 SQL 按序执行；`concept_vote` 等表依赖部分唯一索引兜底并发，勿删。
- 定时任务（概念 36h 超时扫描、留痕截止收口、总结失败重试）随 Java 进程运行，**只部署单实例**，多实例会导致重复执行（业务层有 CAS 兜底，但通知会重复）。
- 日志：`logs/` 目录需可写；操作日志（`oper_log`）已做字段级密码脱敏，密码类存量数据需用 `java/scripts/fix_oper_log_passwords.sql` 清洗。
